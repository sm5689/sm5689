# Setup

Two separate bugs were causing the blank spots. Neither was a markdown problem.

---

## Bug 1 — file paths

Your repo is flat. Everything landed at the root:

```
sm5689/
├── README.md
├── SETUP.md
├── gen_whoami.py
├── snake.yml          <-- GitHub will never read this here
└── whoami.svg
```

The README was asking for `./assets/whoami.svg`, which does not exist, so the
animated terminal rendered as a broken box.

**Fixed:** the new README points at `./whoami.svg` at the root, matching what
you already have. No folder needed for that one.

### But snake.yml MUST move

GitHub only executes workflows from one exact path. A YAML file at the repo root
is an inert text file — Actions never sees it, which is why the snake never
generated. This one cannot stay flat.

Target layout:

```
sm5689/
├── .github/
│   └── workflows/
│       ├── metrics.yml
│       └── snake.yml
├── README.md
├── gen_whoami.py
├── whoami.svg
├── metrics.svg        <-- generated by Actions
└── snake.svg          <-- generated by Actions
```

**To create folders in the GitHub web UI:** click **Add file > Create new
file**, then type the full path into the filename box:

```
.github/workflows/snake.yml
```

Typing `/` turns the preceding text into a folder. There is no separate
"new folder" button. Delete the old root-level `snake.yml` afterward.

## Bug 2 — the stats cards were never going to work

The four broken boxes in Featured Work and Metrics all came from one host:
`github-readme-stats.vercel.app`. That is a single shared instance used by
hundreds of thousands of profiles, and in 2026 it has been returning
`503 DEPLOYMENT_PAUSED` and hitting Vercel's new free-tier rate limits. Nothing
you configure fixes it. Adding `&cache_seconds=86400` only reduces how often you
hit it.

Notice which images *did* render in your screenshots: shields.io badges, the
streak card, the LeetCode card. Those are different hosts and they are fine.
Only github-readme-stats was down.

**Fixed by removing the dependency entirely.** `metrics.yml` generates
`metrics.svg` as a real committed file in your repo. GitHub then serves your own
file. It cannot rate-limit you, cannot 503, and works offline of any third party.
This is also the maintainers' own recommended direction — static SVG generation
via Actions instead of a shared runtime service.

## Order of operations

### 1. Move snake.yml and add metrics.yml
Both into `.github/workflows/` using the path trick above.

### 2. Create the METRICS_TOKEN secret
`metrics.yml` needs a token to read your profile.

1. GitHub **Settings > Developer settings > Personal access tokens > Tokens (classic)**
2. **Generate new token**, scopes: `repo` and `read:user`, no expiration
3. In the `sm5689` repo: **Settings > Secrets and variables > Actions > New repository secret**
4. Name it exactly `METRICS_TOKEN`, paste the token

### 3. Run both workflows by hand once
**Actions** tab, pick each workflow, **Run workflow**. Until they run,
`metrics.svg` and `snake.svg` do not exist and those two images stay broken.
This is expected, not a new bug.

### 4. Verify
Reload your profile. Everything should render. If `metrics.svg` is missing,
open the Actions run log — a failed run is almost always a missing or
wrong-scoped `METRICS_TOKEN`.

## A note on the editor Preview tab

Some external images render unreliably in the **Preview** pane while editing,
because the content is not committed yet and GitHub's image proxy has nothing to
cache. Relative paths like `./whoami.svg` in particular will not resolve there.

Judge the result on your actual profile page, not the preview pane.

## Editing the animated terminal

Change the `LINES` list in `gen_whoami.py`, then:

```bash
python3 gen_whoami.py
```

Clip widths, keyframe percentages, and canvas height all recompute. Commit the
regenerated `whoami.svg`.

`gen_whoami.py` and `SETUP.md` sitting in your profile repo are harmless, but if
you want a clean root you can move them into a `meta/` folder — just update the
README's `src` if you move `whoami.svg` with them.
